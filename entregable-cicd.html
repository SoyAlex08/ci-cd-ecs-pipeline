Objetivo

Configurar un pipeline de CI/CD que construya una imagen Docker, la suba a un registry en la nube y despliegue la app automaticamente cada vez que se hace push a la rama main.

Que hice

Use la app sencilla de nginx que ya tenia de una semana anterior (un Dockerfile + un index.html). Cree un repositorio nuevo en GitHub (SoyAlex08/ci-cd-ecs-pipeline) y ahi arme el pipeline con GitHub Actions.

El pipeline hace tres cosas cuando detecta un push a main:

1. Construye la imagen Docker.
2. La sube a Amazon ECR (el registry de imagenes de AWS).
3. Actualiza la Task Definition de ECS con la imagen nueva y despliega en el servicio de ECS Fargate.

Para que GitHub Actions pudiera autenticarse contra mi cuenta de AWS sin guardar llaves de acceso, configure un rol de IAM que se asume via OIDC (el propio GitHub le pide a AWS un token temporal en cada ejecucion). La infraestructura de AWS (repositorio ECR, cluster ECS, rol de ejecucion, red) la cree una sola vez con un script de AWS CLI antes de correr el pipeline.

Archivo del pipeline (.github/workflows/deploy.yml)

name: Build, Push and Deploy to Amazon ECS

on:
  push:
    branches: [ main ]
  workflow_dispatch: {}

env:
  AWS_REGION: us-east-1
  ECR_REPOSITORY: aws-ecr-ecs-demo
  ECS_CLUSTER: demo-cluster
  ECS_SERVICE: demo-service
  ECS_TASK_DEFINITION: ecs-task-definition.json
  CONTAINER_NAME: demo-app

permissions:
  id-token: write
  contents: read

jobs:
  build-and-deploy:
    name: Build image, push to ECR y desplegar en ECS
    runs-on: ubuntu-latest

    steps:
      - name: Checkout del codigo
        uses: actions/checkout@v4

      - name: Configurar credenciales AWS (OIDC)
        uses: aws-actions/configure-aws-credentials@v4
        with:
          role-to-assume: arn:aws:iam::590251390369:role/github-actions-ecs-deploy
          aws-region: ${{ env.AWS_REGION }}

      - name: Login en Amazon ECR
        id: login-ecr
        uses: aws-actions/amazon-ecr-login@v2

      - name: Build, tag y push de la imagen Docker
        id: build-image
        env:
          ECR_REGISTRY: ${{ steps.login-ecr.outputs.registry }}
          IMAGE_TAG: ${{ github.sha }}
        run: |
          docker build -t $ECR_REGISTRY/$ECR_REPOSITORY:$IMAGE_TAG .
          docker push $ECR_REGISTRY/$ECR_REPOSITORY:$IMAGE_TAG

          docker tag $ECR_REGISTRY/$ECR_REPOSITORY:$IMAGE_TAG $ECR_REGISTRY/$ECR_REPOSITORY:latest
          docker push $ECR_REGISTRY/$ECR_REPOSITORY:latest

          echo "image=$ECR_REGISTRY/$ECR_REPOSITORY:$IMAGE_TAG" >> "$GITHUB_OUTPUT"

      - name: Renderizar nueva Task Definition con la imagen actualizada
        id: render-task-def
        uses: aws-actions/amazon-ecs-render-task-definition@v1
        with:
          task-definition: ${{ env.ECS_TASK_DEFINITION }}
          container-name: ${{ env.CONTAINER_NAME }}
          image: ${{ steps.build-image.outputs.image }}

      - name: Desplegar Task Definition en el servicio ECS
        uses: aws-actions/amazon-ecs-deploy-task-definition@v2
        with:
          task-definition: ${{ steps.render-task-def.outputs.task-definition }}
          service: ${{ env.ECS_SERVICE }}
          cluster: ${{ env.ECS_CLUSTER }}
          wait-for-service-stability: true

Conclusion

El pipeline quedo funcionando de punta a punta: cada push a main dispara el build, sube la imagen a ECR y actualiza el servicio en ECS sin que yo tenga que hacer nada manual. Lo mas complicado fue la parte de permisos entre GitHub y AWS (el rol OIDC), el resto fue bastante directo.
